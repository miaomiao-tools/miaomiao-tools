## .3 候选 · 2026-09-17

**当前真实游戏的显示与基本鼠标移动已确认正常。** 维护者直接观察到面板覆盖在游戏上；用户随后明确确认前进、后退，以及松开或移出按钮后停止移动正常。维护者没有代发游戏移动输入，也没有中断用户继续试玩。

### 不显示的原因与修复

旧版现场的所选游戏完整路径与真实进程一致，前台句柄也正确。助手 Visible=true、未最小化、未被系统隐藏，位置完全在游戏画面内，双方 DPI 一致。问题是助手实际原生样式缺少 TOPMOST 位，窗口层级在游戏后面，面板中心命中游戏。

只读检查本机 .NET Framework 代码确认：Opacity 切换 layered 样式时会按 CreateParams 写回扩展样式，而旧助手的 CreateParams 没有保留 TopMost 位。这能使托管属性仍为 true，原生置顶状态却已丢失。旧版从压缩软件临时目录运行是现场事实，但不是这次显示故障的根因。

修复在 CreateParams 保留置顶位，显示或返回游戏时仅恢复本助手的层级；每 500 毫秒检查实际标记，丢失后才再次恢复。原生调用保留位置、大小、焦点和 owner 排序，不主动显示已隐藏面板，选择或退出期间也不恢复。完整路径匹配、前台校验、按键与守护逻辑保持原有保护。

修复后的只读采样确认助手 TOPMOST=true，位于游戏之前，面板中心命中助手；游戏保持前台。仅确认当前机器和当前游戏状态，不将画面尺寸视为独占全屏已验证。原生层级调用参考 [Microsoft SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

## .2 上一候选


面向 Windows 10 / 11 x64、.NET Framework 4.8 / 4.8.1。游戏及助手应使用相同的普通权限。建议窗口化或无边框；独占全屏、权限不一致或游戏更新可能影响显示或输入识别。ARM64 不在当前验证范围。

该候选版在一台 Windows 11 x64 机器完成离线自测：按键状态机、Windows 输入结构尺寸、游戏路径选择、取消、持久化和完整路径匹配。离线测试不安装钩子、不创建游戏窗口、不发送真实输入，只写指定报告及同目录临时测试文件。

当前文档对应 **0.1.0-experimental.2 本地候选**，尚未公开；已发布的 .1 附件保持原样。新增回归覆盖按住时切换、选择期间阻止输入、保存失败保留旧配置、两个同名安装目录及重启后读取新路径。中英说明与两张展示图均随本地候选包附带；应用界面仍为中文。

维护者已在 **--demo 真实助手测试窗口** 实测：点击前进/后退并成对释放 W/S、短拖出按钮后释放、空闲时切到其他软件再返回、关闭训练窗口后助手和保护进程退出，以及重新打开后的 W/S 点击。短拖出场景的 W 约 22 毫秒后释放，不能将其记作长时间按住测试。截图也是此测试窗口，**不是游戏画面，不代表完成游戏实测**。

最终程序还从全新解压目录完成 --demo 点击/松开、S 按下后拖出（约 6 毫秒释放）、零场景误点及正常退出。

在**预置有效游戏位置的独立测试配置**下，已实际打开普通模式的「重新选择游戏…」，用 Escape 取消后配置字节不变；再次通过原生文件名框选择同一已安装游戏，成功保存、没有残留临时文件，退出重开直接出现面板、不再询问位置。这不是首次选择测试，也没有切换到另一份真实安装。

**本轮未完成实测**：首次选择、另一真实安装切换、原生交互中的选错/保存失败、长时间按住、按住时切换软件或退出、Steam 启动、异常退出守护、独占全屏、多屏/DPI、Windows 10、其他语言系统或真实游戏内体验。初选框实际存在，但桌面工具无法枚举其隐藏 owner 下的窗口，不能将这一访问限制写成通过或程序死锁。错误选择、保存失败、按住时重选和异目录同名目标已由离线回归覆盖。

实验程序没有数字签名。若系统提示未知发布者，应核对来源和 SHA-256；不需要关闭系统安全防护。源码及构建步骤见 BUILD.md。
